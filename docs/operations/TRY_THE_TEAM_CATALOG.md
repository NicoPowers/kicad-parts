# Try the team catalog by hand

This starts a throwaway team server on your computer and opens the desktop app connected to it. You can then edit a resistor, move a part to another category, replace its footprint with a file, see its history, archive a revision, review new CSV values that an import did not apply, see the library check, add a part from our libraries, browse every symbol and footprint library, and place the team's parts in KiCad. Nothing you do changes the CSV catalog or anything else in the repository.

To check that your whole CSV catalog can move into a team catalog without losing anything, see [Check that your CSV catalog can move to a team catalog](MOVE_THE_CSV_CATALOG.md).

## Build once

From the repository root, in PowerShell or Git Bash:

```
cd apps/desktop-ui
trunk build
cd ../..
cargo build --locked -p kicad-parts-desktop --features custom-protocol
```

You need KiCad 10 installed for the symbol and footprint previews.

## Start it

```
cargo run --locked -p catalog-import -- local-team-server --desktop
```

The command:

1. starts PocketBase on `127.0.0.1` with a random port, with no window and no browser;
2. imports every CSV file in `database/` (`g-*.csv`), so all 178 parts and all 21 categories are there, one category per CSV file; this takes about 12 seconds (add `--csv g-res,g-cap` to import only some files, which is faster);
3. creates three accounts with new random passwords and prints them;
4. opens the desktop app with the server address and the first email already filled in.

The accounts are:

| Email | Can do |
| --- | --- |
| `editor@example.test` | view and edit parts |
| `second.editor@example.test` | view and edit parts (use it in a second app window to cause a conflict) |
| `viewer@example.test` | only view parts |

## What to try

1. In the app, open **Team catalog: not signed in** at the top right and sign in with the first account's password from the console.
2. Search for `RC0603FR-0747RL` and select it. The right-hand column shows **Details** and **History**.
3. The details show the part's **Category** by name, such as "Category: Resistors". Choose **Edit part**, change a value, give a reason, and save. The part details change, but the part gets no new revision: every revision shares the same details. Only changing the **Symbol** or **Footprint** adds a revision. The revision also shows **Excluded from BOM**, which the team server works out from the symbol and footprints the revision uses, never by hand. It says which mark sets it ("Yes: its symbol says it is not in the BOM"), "No: only some footprint choices say it is not in the BOM" when the choices disagree, and "Not known" when the answer depends on a symbol or footprint the server cannot read: one from KiCad's own library, which the app does not read yet, or one that is not in the Catalog.
4. To move a part to another category, choose **Edit part** and pick one under **Category**. The part keeps its IPN and every field it has; the fields of the new category that the part lacks are added below, blank, so you can fill them in. Save with a reason. The history shows the change by category name. Changing a category also records remembered matches: the part's footprint family, reference letter and manufacturer, kept for that category. Add part uses them to guess a new part's category.
5. To see a conflict, keep the first app open and open a second copy pointed at the same server, with its own settings folder:

   ```
   target/debug/kicad-parts-desktop.exe --team-server=<address> --data-dir=<an empty folder>
   ```

   Sign in there as `second.editor@example.test`. In the first app, choose **Edit part** on the part and change something, but do not save yet. In the second app, save a different change to the same part (for example the first app changes the tolerance and the second the value). Now save in the first app: it shows where you started, what they saved and your changes, and lets you save your changes on top of theirs. If both apps make exactly the same change, there is no conflict: the app says "These changes are already saved, so nothing more was saved." A file chosen with **Use a file…** always counts as your change, even the same file the other person chose: the app still shows the conflict, and saving on top of theirs then saves nothing. Changes saved in one app appear in the other by themselves.
6. To replace the footprint with a file, copy `footprints/g-Resistor_SMD.pretty/R_0603_1608Metric.kicad_mod` to a folder of your own and change it in KiCad's footprint editor. In **Edit part**, choose **Use a file…** under **Footprint** and pick your copy. No symbol or footprint name is typed: **Symbol** and **Footprint** show the chosen reference, read only (you can still select and copy it). The app takes the name from the file, lets you choose its library from a list of our libraries (the suggested one is chosen already), draws the footprint, and, if the footprint names a 3D model in the Catalog's `3d-models` folder that the Catalog does not have, asks for that file too (leave it out and the save is refused, because the footprint would have no 3D model). A footprint whose 3D model link points anywhere outside the Catalog's `3d-models` folder, such as a folder in your home folder, is refused too: such a link only works on one computer. Give a reason and save: the footprint gets a new revision, only this part moves to it, and the message says how many other parts still use the older one. **History** shows the file the new revision came from. A `.kicad_sym` with several symbols asks which one to use. A later import never replaces a footprint changed this way; if the CSV catalog's file for it changes, the part shows the CSV notice, and that value can only be kept.
7. To add a part from CAD files you downloaded (from SnapEDA, Ultra Librarian, SamacSys or a manufacturer's site), choose **Add part** beside **Search parts**, then **Upload a ZIP…**, and choose the ZIP file, or its `.kicad_sym`, `.kicad_mod` and 3D model files. The app reads them without unpacking anything, draws the symbol and footprint, and fills in what the symbol says (MPN, manufacturer, description, value, datasheet); anything no field takes is listed so nothing is lost. It guesses the category and says why ("Best guess: Capacitors, because footprint C_0603 matches C_*"), offers the next free IPN for it (you can type another), and checks before you save: a part that already has the MPN (open it instead, or add the MPN to it as a manufacturer part), a footprint the Catalog or KiCad already has (use it instead of a near-copy), and whether the symbol's pins and the footprint's pads agree. To use a symbol or footprint the Catalog or KiCad already has instead of the download's, such as `g-cap:C` or `Device:C`, choose **Choose…** under **Symbol** or **Footprint** and choose it in the Libraries browser; the download's file is then not saved. The library the download's symbol and footprint go into is chosen from a list of our libraries, never typed. When the footprint's name says no package group, the app suggests one from a Catalog footprint with the same pads, or from the category. The license is recorded as unknown, needs review. The footprint's 3D model path is set to the Catalog's folder for the footprint's library, so KiCad finds the model; the history says so. If you choose no 3D model, the download's own link to its vendor's folder is left out, because it only works on the vendor's computer. Give a reason and save: the part opens with its drawings and history, which lists the files it came from, and others see it by themselves. Confirming the category records remembered matches, so the next guess is better. Without a download of your own, put copies of `symbols/g-cap.kicad_sym` and `footprints/g-Capacitor_SMD.pretty/C_0603_1608Metric.kicad_mod` in a ZIP file; as the Catalog already has that footprint, the app offers to use it. Add part reads the CSV files in its folder again just before it saves. If a row there took the IPN in the meantime, the app saves nothing and offers the next free IPN. While a team moves to the team catalog, give new IPNs in one place; see [Give new IPNs in one place while you move](MOVE_THE_CSV_CATALOG.md#give-new-ipns-in-one-place-while-you-move).
8. Open **History**. Each entry is one saved change: a change to the part details, a new revision, or an archived revision. Select one to see what changed, who changed it, when and why. Nothing is ever deleted or changed afterwards, and there is no way to copy an older revision back.
9. To take a bad revision out of use, select it in **History** and choose **Archive revision N…**, then give a reason. The app stops offering it, and KiCad lists it only under **Archived revisions**, so nobody new picks it by mistake; designs that already use it keep it. The current revision becomes the newest one that is not archived. **Unarchive revision N…** undoes it. The only revision that is not archived cannot be archived: add a corrected revision first.
10. To see what an import does to a part edited in the app, edit the part's **Description** and **Value**, then type `reimport` in the console and press Enter: it imports the resistors again. The import leaves the edited part as it is, and the app shows nothing: the CSV has no new values. Now give the import new values without touching the repository: copy the `database`, `symbols` and `footprints` folders into an empty folder, change the part's value in the copy's `database/g-res.csv`, and type `reimport <that folder>`. The import still leaves the edited part as it is, and the app shows by itself: "g-res.csv has new values for this part. They were not applied, because the part was edited in this app." Choose **Review CSV values**. Each field whose CSV value differs is listed with its value now and in the CSV. Values the CSV changed come first; values it did not change are marked "(not changed in the CSV)", and accepting one undoes the edit. Tick the ones to accept and choose **Accept the ticked values**: accepting part details adds no revision, and accepting the Symbol or Footprint adds one. The fields you do not tick stay as they are. **Keep current values** accepts none. Either way the notice goes away, and it comes back only if the CSV changes again, even back to what it said before, unless someone already reviewed those exact values. Typing anything else gets a reminder; Enter alone stops the team server. To see a CSV row that may give a part's IPN to another part, add a resistor with **Add part**. Then add a row with its IPN and another MPN to the copy's `database/g-res.csv`, and type `reimport <that folder>`. The import leaves the part as it is, and the part shows "A CSV row has this part's IPN". It offers nothing to review. It says what to do if the row is a different part (give it the next free IPN, which it names) or the same part (put the part's MPN in the row, or remove the row).
11. Signed in with an account that can edit, a line under the search box, such as "Library check: 32 new items", says what the CSV catalog's own libraries (`symbols/g-*`, `footprints/g-*`, `3d-models/`) have that the Catalog does not, and what to fix. Engineers may still draw symbols and footprints in KiCad; this is how the app notices them. Choose the line to open the **Library check** view: **To fix** lists problems that stop the next import that uses them, and Add part or Edit part with them; **Not in the Catalog yet** lists symbols, footprints and 3D models that no part uses, probably drawn in KiCad (power symbols such as GND, which never become parts, are left out); **Worth a look** lists things to check, some of which need fixing before a part uses them, such as a footprint no part uses yet whose 3D model link only works on one computer, a 3D model shared by two footprints, or a CSV row naming `g-ics:TP4333` when the library has `IC_TP4333`; **Clean-up** lists old problems of footprints unchanged since they were imported, which stop nothing. A footprint's 3D model link is fine when it points into `${GITPLM_PARTS}/3d-models/g-<footprint library>.3dshapes/` with the footprint's name, or at KiCad's own models; a link to a file missing from that folder is a problem too, and a link anywhere else, such as `${GITPLM_3DMODELS}` or a folder in someone's home folder, only works on one computer. It is to fix when the footprint changed since its import, or when a CSV row starts using a footprint the Catalog does not have; only footprints still exactly as they were in today's CSV catalog keep their old problems as clean-up at their CSV file's first import. The team server refuses such a link in Add part and Edit part too. To see an import refused, copy the `database`, `symbols`, `footprints` and `3d-models` folders into an empty folder, change the 3D model path in the copy's `footprints/g-Resistor_SMD.pretty/R_0603_1608Metric.kicad_mod` to `C:/Users/me/R_0603.step`, and type `reimport <that folder>`: the console says the import was refused and lists the file and what to fix; nothing was sent. The CSV import (`catalog-import pilot`) prints the same check before it sends anything.
12. To add a part from a symbol and footprint already in our libraries (drawn in KiCad, or committed by someone else), choose **Add part from it** beside one in **Not in the Catalog yet**, or choose **Add part**, then **From a library…**, and choose it in the Libraries browser. Choosing a symbol also brings the footprint it names. The part uses them exactly as they are in the library, under the same names. The footprint keeps its own 3D model link; the model is saved with it when the link points into our library. The form runs the same checks as for a download, plus what the library check found about these items. A 3D model link outside our library, a missing 3D model file, or files with changes that are not committed stop the save: the history names each file and the commit it was read from, so commit first. To use a symbol or footprint the Catalog already has, choose it with **Choose…** under **Symbol** or **Footprint**; it is used as the Catalog has it. Once saved, the items leave **Not in the Catalog yet**. The CSV catalog files are not changed; a CSV row added later that names the same files finds nothing to change.
13. Choose **Libraries** in the header to browse symbols and footprints, signed in or not. On the left are three groups: **Ours** (the CSV catalog's `g-` libraries), **KiCad** (KiCad's own libraries) and **Installed** (other libraries you added to KiCad, read from your KiCad library tables, never changed). The first time, the app reads them all in the background and says how far it is; you can browse what is ready. Later it reads only libraries that changed. Search by name, description or keywords, and filter symbols by pins, reference letter, power symbols and default footprint, or footprints by pads and SMD or through-hole. Select an item to see its drawing and details. The drawing zooms and moves as in the close-up (step 15), and **Enlarge** opens the close-up. **Show matching footprints** lists the footprints that fit a symbol, with KiCad's two filters: its footprint filters and its pin count. Items a part uses say **In the Catalog**, and **Show the parts that use it** searches for them. Signed in with an account that can edit, one of our items that no part uses offers **Add part from it**. Close the browser with **Close**, Escape or a click outside it.
14. In **Edit part** and **Add part**, **Choose…** under **Symbol** or **Footprint** opens the Libraries browser for that role, with the current item selected and drawn, so you see what replaces what. With the keyboard, the list has the focus: the arrow keys move, Enter chooses, and Escape closes; focus goes back to **Choose…**. For a footprint, the browser starts with KiCad's two filters on for the part's symbol. What choosing does depends on where the item lives. An item the Catalog has is used as the Catalog has it. One of our items that the Catalog does not have yet is added from our libraries when you save, as it is committed, as in step 12. One of KiCad's own is referred to as KiCad's, as imported parts are, because every engineer has KiCad. An item of another installed library, which teammates may not have, is copied into one of our libraries, chosen from a list, like a download: its 3D model comes with it when the app can read it (through your KiCad path variables), and the link is set to our library's folder. The **3D model** choice lists each file it copies and the link it comes from. Only KiCad's 3D model files (`.step`, `.stp`, `.stpz`, `.wrl`, `.wrz`) are copied, and a link with no folder and no path variable is not read. If the model cannot be read, **Save** is off and the form says why; choose **No 3D model** to copy the footprint without it. The history names the installed library and file each copy came from. A part with several footprint choices keeps them as a list: **Add another…** adds one and **Remove** takes one out. **Add part** starts with **Upload a ZIP…** or **From a library…**; a generic part from KiCad or another library gets a category, an IPN and part details as usual. To try copying, add a footprint library of your own to KiCad (**Preferences > Manage Footprint Libraries**), then choose one of its footprints in **Edit part**.
15. Click a symbol or footprint drawing to open its close-up. This works for a part's drawings, and for the drawings of a file you chose or downloaded in **Edit part** and **Add part**. Scroll to zoom where the pointer is, and drag with the left or middle mouse button to move the drawing. **Fit** shows all of it again. With the keyboard, Tab to the drawing: plus and minus zoom, the arrow keys move it, and 0 fits it. A footprint is drawn from its file, layer by layer, and the pointer's position is shown in millimetres. Zoom in far enough to look at one pad closely. The **Layers** list shows only the layers the footprint uses. Tick or untick a layer to show or hide it, for example to compare the paste (stencil) openings with the copper. Choose a layer's name to make it the active layer, drawn on top; **Dim the other layers** makes it stand out. Paste and mask openings follow the pad's and the footprint's own settings; a board's own settings can change them. A symbol keeps the drawing kicad-cli makes and has no layers. The close-up closes with **Close**, Escape, or a click on the dim area around it.
16. In a footprint's close-up, choose **Measure** (or press M) to measure. Click a start point and an end point; the line follows the pointer until you click the end. A third click starts a new measurement. Points snap to the nearest point on the active layer, such as a pad's centre, corner or edge middle, or a line's end. The yellow square shows where a click will snap, and the pointer's readout names it. Hold Shift to place a point anywhere. Under the drawing, the app shows the distance, its X and Y parts, and the names of the two points. When both points are on pads, it also shows the gap between the two pads on the active layer. To compare the stencil with the copper, make **F.Paste** the active layer. The points move to the same kind of point on each pad's paste opening, such as its corner, and the gap is measured again. A point with no match on the new layer stays where it was, and the readout names its layer. **Units** switches between millimetres and mils for the rest of the session. With the keyboard, press N (or Shift+N to go back) to step through the snap points, and Enter to pick one. Escape clears the measurement; a second Escape closes the close-up. The middle button still moves the drawing, and the wheel still zooms.
17. In a footprint's close-up, choose **3D** to see the footprint on a small board with its 3D model, so you can check that the model sits right on the pads. The first time takes a few seconds, while KiCad's kicad-cli makes the view; the app says "Making the 3D view…". After that it comes from the app's cache. Drag with the left button to turn the model, scroll to zoom where the pointer is, and drag with the middle or right button to move the view. With the keyboard, Tab to the view: the arrow keys turn it, Shift and an arrow key move it, plus and minus zoom, and 0 goes back to the start. **Reset view** goes back to the start, which looks down at the front. **Top** and **Bottom** look straight down and straight up; Bottom is mirrored, as in KiCad. The **3D model** panel lists each model link in the footprint. For each, it says where the file was found (the Catalog, our library, KiCad's own library, an installed library, or a file you chose) and gives its full path. If a model can't be shown, it says why: the file is missing, a path variable isn't set in KiCad's path settings, the file isn't a 3D model, kicad-cli couldn't read it, or KiCad's hide flag hides it. For a footprint from a download in **Add part**, the app shows only the download's own 3D model: the footprint's other links point at its maker's computer. The app never opens a network folder, such as `\\host\share`, unless it comes from a path variable you set in KiCad. If no model can be shown, you still see the board with its pads, silkscreen and mask. Choose **3D** again to go back to the drawing. If your computer can't draw 3D (WebGL is off), the app says so and keeps the drawing.

18. To place the team's parts in KiCad, open the KiCad settings at the top right (the green **KiCad 10** badge). The **KiCad libraries** section makes KiCad libraries from the team catalog while you are signed in.
19. The libraries are named with the **team code**, such as `MA`: `MA-Parts` holds the parts, and footprint libraries are named like `MA-Resistor_SMD`. The code belongs to the team, so every member gets the same names. If the team has no code yet, someone who can edit chooses one: type 2 or 3 capital letters or digits, choose **Choose code…**, read the confirmation and choose **Use MA**. Boards save these names, so the code never changes in the app. The app warns you if another team's libraries on this computer already use that code. If they do anyway, KiCad can't hold both, so the app makes no libraries for this team and says so, naming both team servers. A superuser of this team's server then changes its code, as in [Fixing a mistaken team code](#fixing-a-mistaken-team-code). A member who cannot edit sees who to ask. No libraries are made until the team has a code. To start the team server with a code already chosen, add `--team-code MA` to the command.
20. Once the team has a code, the app updates the libraries after signing in, and again about 2 seconds after someone saves a change. **Update now** updates them at once, and **Open folder** shows them. The status line says when they were last updated, or why the last update could not run; the app then tries again. If another update of the same folder is running, such as from a second copy of the app, the app waits its turn. Each team has its own folder, such as `kicad-libraries\MA`. Signing in to a team updates only its folder; other teams' folders stay as they are and are listed below.
21. Each revision of a part is its own entry, such as `RES-0000-0470_v2`, so a design never switches to newer CAD by itself. The IPN field and the BOM keep the plain IPN, and the revision has its own field. KiCad shows each category as one group, such as `MA-Parts - Resistors`. Older revisions are under **Older revisions**, and archived ones under **Archived revisions**. Symbols and footprints get revision names too, such as `R_US_v2`. A symbol or footprint from KiCad's own libraries stays a link to KiCad's library.
22. To add the libraries to KiCad once, follow **Add them to KiCad once**. Choose **Copy** beside **Symbol libraries**. In KiCad, choose **Preferences > Manage Symbol Libraries**, right-click the table on the **Global Libraries** tab, choose **Paste**, then **OK**. Do the same with the footprint libraries in **Manage Footprint Libraries**. When the app names new libraries, copy and paste again. KiCad reads the parts through the SQLite3 ODBC driver; the app says whether it is installed.
23. New parts and revisions reach KiCad within about 10 seconds: close and open the **Add Symbol** window. A new category, or a change to a category's fields, needs KiCad to restart; the app says so while an older KiCad is still running. The generated files are read-only. If one was changed anyway, the app names it and keeps it; delete it and update again to write it from the team catalog. KiCad still lets you save a new footprint into a generated footprint library, because it checks the folder, not the files. The app names such a file and leaves it alone, but no one else on the team gets it.
24. With `--desktop`, the libraries are in the command's own folder and are deleted when it stops. Your own app keeps them in `%LOCALAPPDATA%\org.kicadparts.desktop\kicad-libraries`. To make them without the app, run `cargo run --locked -p catalog-import -- kicad-libraries --team-code MA <folder>`.

## Stop it

Close the desktop app. The command then stops the team server and deletes its data. Ctrl+C or closing the console window does the same.

The team server keeps its data in `target/local-team-server/run-<number>` while it runs, never in your system temp folder. The data includes the accounts' password hashes. If the command is killed outright (for example from Task Manager), the team server still stops, because it runs in a job that Windows ends with the command, but the folder stays behind until the next time you start the command, which deletes it.

If the team server will not start and says its data "cannot be upgraded", the data was saved by an older version of the team server: before parts had a category, before part details were kept apart from revisions, or before CAD item revisions were numbered like part revisions. That data is never changed. To start fresh, stop the command, delete the `target/local-team-server` folder, and start the command again. If you run PocketBase on a data folder of your own, delete or move that `pb_data` folder instead.

Without `--desktop`, the command prints the address and accounts and waits for you to press Enter or Ctrl+C, so you can open the app yourself.

## Fixing a mistaken team code

The app never changes a team code, because boards save the library names it makes. If a team chose the wrong code and no board uses its libraries yet, a PocketBase superuser can fix it: open the PocketBase dashboard, open the `team_settings` collection, and change or clear `code` in its only record. Then every member signs out of the team catalog and signs in again, because the app reads the team's settings only when someone signs in. Each member also closes KiCad, deletes their `kicad-libraries\<old code>` folder, removes the old libraries from KiCad's library tables, and adds the new ones. Do the same when the app says another team's libraries on this computer already use the team's code.

## How signing in works

- The app saves only the server address and your email (in `team.json` in its settings folder). It never saves your password or the sign-in session; after a restart you sign in again.
- For now the app only connects to a team server on this computer (`http://127.0.0.1`, `localhost` or `[::1]`). Live updates use plain HTTP, and a password must not cross a network unencrypted. Connecting to a shared server needs HTTPS first.
- Members marked "can edit catalog" in PocketBase can edit, archive and review CSV values. Everyone else who signs in can only view. Only an administrator can change that mark, or a member's name, which the history shows as the author of each change.
