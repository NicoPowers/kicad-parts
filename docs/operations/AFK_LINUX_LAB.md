# AFK Linux lab

The lab's single entry point is:

```text
cargo xtask test-afk
```

The command validates `infra/versions.lock`, creates a unique Compose project and internal network, generates run-scoped test credentials, validates the normalized Compose mount policy, starts PocketBase and MinIO without publishing host ports, proves their exact internal endpoints from the scoped test-runner, inventories the runner, runs the pinned official KiCad CLI against a read-only fixture, writes evidence, and tears down its own volumes. `cargo xtask test-afk --static-only` performs the lock and normalized-policy checks without starting services. Use `--preserve-on-failure` only for diagnostics; the failure report prints the exact scoped cleanup command.

Evidence is written beneath `.afk/runs/<run-id>/artifacts/` and includes JUnit XML, logs, the actual environment/image manifest, isolation and teardown reports, and lane status (`passed`, `failed`, or `not-run`). Every artifact entry must be a non-link regular file; directories, symlinks/reparse points, sockets/devices, special files, metadata errors, and undeclared files fail closed. `evidence.json` declares the stable relative path, byte length, and SHA-256 of every other artifact, including the staged JUnit file, then the finalized directory is re-hashed and compared exactly. The evidence file is the sole explicit self-hash exclusion, avoiding a self-referential digest cycle. The final JUnit and JSON manifest are staged and finalized only after teardown, so a passing bundle cannot describe resources that still exist. Runtime credentials exist only in process memory and the child Compose environment; they are never written to state or evidence. The run state contains only validated metadata plus a run-scoped canary, and is deleted on normal teardown. Secret values are redacted from logs.

The test-runner receives no host bind mounts. The KiCad service receives exactly the representative smoke fixture at `/fixture` (read-only) and that run's artifact directory at `/artifacts` (writable); it never receives the repository. The host home, KiCad installation/configuration, Docker socket, SSH agent, credential stores, existing service state, and `secrets.env` are never mounted or sent in a Docker build context. PocketBase and MinIO use Compose-project-scoped named volumes; all HOME, XDG, and KiCad paths are container-local.

Compose enforces exact runtime ceilings in the normalized model: PocketBase is limited to 256 MiB and 128 PIDs; MinIO to 1 GiB and 256 PIDs; the test-runner and KiCad CLI to 2 GiB and 512 PIDs each. Every `/tmp` tmpfs is exactly 128 MiB and every HOME, XDG, and runner/KiCad configuration tmpfs is exactly 64 MiB. These private, container-local mounts use sticky mode `01777`, allowing the fixed non-root identity to create its own mode-`0700` XDG/KiCad leaf directories without granting cross-container access. Missing, zero, changed, oversized, duplicate, or additional resource/tmpfs settings are rejected before build or service start. Runtime probes execute as UID/GID 65532 and verify the cgroup ceilings, tmpfs root owner/mode/size/mount options, leaf owner/mode, and a create-read-delete canary in every writable target. Exact results are recorded in `runtime-isolation.json` and per-service logs; permission, read-only-state, or configuration errors invalidate otherwise successful-looking output.

`--preserve-on-failure` leaves only the named run's scoped containers, network, volumes, image tags, state metadata, canary, and evidence for diagnosis. It prints a shell-safe cleanup command of the form `cargo xtask cleanup-afk --run-id <run-id>`. Cleanup reconstructs and validates the original run scope from state, removes only that scope, verifies no scoped Docker resources remain, removes the run-scoped image tags, and then deletes state. Reusing an existing run ID is rejected rather than overwriting evidence.

The official `kicad/kicad` image is authoritative only for CLI/file integration. KiCad explicitly does not support its GUI in Docker. `.github/workflows/kicad-gui-smoke.yml` defines the supported clean Ubuntu 24.04/X11 lane. The checked-in `fixtures/kicad-10/gui-config` fixture deterministically satisfies KiCad 10's first-start settings, privacy, and global-library predicates: schema-6 common settings acknowledge both privacy prompts; typed version-7 symbol and footprint tables chain to their exact stock tables; and a typed version-7 design-block table is deliberately blank because the exact KiCad 10.0.4 runtime ships no stock `design-block-lib-table`. A hosted run proved that this exact four-file configuration was accepted and only the writable `kicad_common.json` changed, yet the editor still failed to map within 60 seconds. The wizard was therefore not the sole active blocker. Exact KiCad 10.0.4 source shows that the direct `pcbnew` launcher constructs the PCB frame before it checks the start wizard, while `kicad --frame pcb --software-rendering <board>` selects the same real `FRAME_PCB_EDITOR`, sets `KICAD_SOFTWARE_RENDERING=1` before frame construction so the canvas resolves to Cairo, skips the manager-only start wizard, loads the global tables, and opens the positional board through `OpenProjectFiles`. The lane uses that exact dispatcher path rather than speculating about D-Bus or installing additional packages.

Before launch the lane preflights the two shipped `/usr/share/kicad/template/{sym-lib-table,fp-lib-table}` targets, verifies the ordered source `SHA256SUMS`, makes the source directory and files read-only, copies only the four declared files into the run-scoped `$KICAD_CONFIG_HOME/10.0`, makes that copy writable for KiCad, and verifies and records the copied hashes. Configuration readiness failures are retained in a dedicated artifact. After the dispatcher is stopped, the cleanup trap records a best-effort post-run hash snapshot and copies only the isolated, non-link `$KICAD_CONFIG_HOME/10.0/kicad_common.json` into diagnostics; these reads never inspect process environments or credential locations and cannot mask the original exit status. The lane also records `/usr/bin/kicad` and `/usr/bin/_pcbnew.kiface` ownership, size, SHA-256, dependencies, and resolved launcher path. It then starts Xvfb, proves X readiness with a bounded `xprop -root` loop while checking Xvfb liveness, and starts the exact-pinned `/usr/bin/openbox --sm-disable` process with an isolated log. It accepts window-manager readiness only while Openbox is alive and when the root `_NET_SUPPORTING_WM_CHECK` property contains exactly one XID whose own `_NET_SUPPORTING_WM_CHECK` points to that same XID and whose exact `_NET_WM_NAME` is `Openbox`. Each X-server and window-manager readiness query is preserved in uploaded evidence; early exits record exact process status, and the cleanup trap waits for KiCad, Openbox, and then Xvfb without waiting twice for a process reaped early.

Only after those fail-closed handshakes does the lane launch exact `/usr/bin/kicad --frame pcb --software-rendering`. The dispatcher main-frame tuple is pinned from the creation order, not guessed: `PGM_BASE::InitPgm` derives lowercase application name `kicad` from exact `argv[0]`; `PGM_KICAD::OnPgmInit` sets application display name `KiCad` before `Kiway.Player`; and wxGTK 3.2's `wxTopLevelWindowGTK::Create` passes the current display name to `gdk_set_program_class` before `gtk_window_new`. KiCad changes the display name to `playerFrame->GetAboutTitle()` only after `Kiway.Player` returns, while the PCB constructor assigns untranslated about title `KiCad PCB Editor` in its body after base/top-level construction, so those later values cannot change the already-created main frame. Across up to 180 attempts separated by one-second retry pauses, the window proof therefore considers only the current root tree and exact case-sensitive resource/class tuple `("kicad" "KiCad")`; titles, substrings, the old direct-launch tuple, stale candidates, and other casing do not qualify. Every raw candidate is queried again by the same XID and must have exactly one `Map State: IsViewable`, dimensions agreeing with the current tree, and a minimum 100×100 size. That explicit threshold rejects the hosted 10×10 bootstrap/helper window; the separately observed 200×200 override-redirect splash remained unmapped and therefore also could not qualify. The workflow enumerates the entire current candidate set and captures only when exactly one candidate qualifies. After capture it obtains a fresh root tree, enumerates and re-queries the entire candidate set again, requires exactly one global qualifier, and requires that sole XID and its dimensions to equal the pre-capture selection. Zero and ambiguous cardinalities are diagnosed and retried, so a helper can be ignored but a second main-sized window or a post-capture replacement/race fails closed. The PNG is truncated before capture, and `identify` must report dimensions matching the selected window and more than one unique color, rejecting stale or uniform captures such as an all-black Xvfb root. Per-attempt dispatcher process status and bounded snapshots at attempts 1, 30, 60, 120, and 180 record the executable, command line, process status, thread summary, and each thread's name, status, wait channel, and current syscall. Every `/proc` read is best-effort, no process environment is read, and snapshot failure cannot mask the lane's primary result. Every numbered pre- and post-capture root tree, candidate detail, cardinality, rejection, image measurement, and process diagnostic remains in the uploaded evidence, and an early dispatcher death records its exit code before the cleanup trap runs. The typed Rust `cargo xtask export-github-env` command exports the PPA, stock paths, ten exact package names, versions, and `package=version` specs, plus the Linux x64 GNU Tauri binding URL and SHA-512, from `infra/versions.lock`; the workflow requires each package version to be available and asserts every installed version again. The exact-pinned APT transactions explicitly allow downgrades because the hosted runner may already contain a newer package (notably Xvfb), and the subsequent `dpkg-query` assertions still require every locked version exactly. The established nine-package transaction remains unchanged; Openbox is installed alone in a separate exact `--no-install-recommends` transaction so minimizing the window manager cannot alter the existing dependency closure. The invoked Ubuntu GUI helpers are limited to their required packages (`x11-utils` for `xwininfo` and `xprop`, the concrete `imagemagick-6.q16` provider for `import` and `identify`, and `openbox` for the window manager), recorded in the machine manifest, and preflighted at their exact `/usr/bin` paths together with `Xvfb`, `kicad`, and `kicad-cli`; unused floating `x11-apps` and `xauth` operands are excluded. The SHA-256-verified Node distribution is extracted without `sudo` into a new run-private toolchain prefix and its explicit `node` and `npm` paths are asserted, so hosted `/usr/local` files cannot mix with or satisfy the pinned toolchain. The Tauri wrapper and its required native binding are downloaded and SHA-512 verified separately, then installed together by that private npm in one offline, script-disabled transaction under the same prefix. This prevents live optional-dependency resolution and global-bin collisions. The single private bin path is propagated through `GITHUB_PATH`; verbose npm output and debug logs are written beneath the always-uploaded artifact directory, using an isolated npm home and no user npm configuration. Python, Python 3, PyQt, and `tomllib` are prohibited from workflow, infrastructure, and AFK tooling scope, with a recursive fail-closed contract scan. Those pins were resolved from the locked official KiCad Noble PPA package index, npm registry metadata, and Canonical's Noble amd64 package metadata recorded in the lock.

A single exhaustive typed workflow-contract table drives structural YAML validation and mutation tests for parsed trigger/job/step fields and human-readable shell semantics: lock/export consumption, package availability/install/assertions, action pins, isolation, exact first-run config path/file set/stock-table preflights/hash verification/copy ordering, GUI launch/window/screenshot/hashes/logs, JUnit/lane evidence, and always-upload behavior. Static fixture validation independently fixes the four file contents, KiCad schema and privacy flags, all three table types, the two shipped stock-table URIs, SHA-256 values, manifest order, and exact file set. The four protected `run` programs (`Export`, `Install`, `Smoke`, and `EnsureEvidence`) also require exact canonical-program digests. Canonical encoding is deterministic and length-prefixed, preserves each physical continuation segment, and ignores only blank and full-line comment lines. Quote, escape, comment-boundary, or continuation ambiguity fails closed. Consequently, moving a required token into `printf`, `echo`, a comment, dead branch, uncalled function, command substitution, or data cannot satisfy the contract, and adding or reshaping executable/control lines changes the digest. Required command ordering is still checked by step and active-line position for readable diagnostics. A Windows host without WSL cannot run that lane locally, and local evidence records it as `not-run` rather than treating Docker/Xvfb as equivalent.

MinIO maintenance risk is explicit: upstream archived the open-source repository on 2026-04-25. The selected last security release, `RELEASE.2025-10-15T17-29-55Z`, has no official Docker Hub or Quay image and its historical binary URL is absent. The lab therefore builds the exact upstream commit and verified source archive with pinned builder/runtime bases, then records the resulting local image content ID. The product plan still selects MinIO; this lab does not silently substitute another backend.

Docker Official helper images use immutable manifest digests. The Rust base is fetched through Amazon Public ECR's Docker Official Images mirror to avoid Docker Hub's unauthenticated rate limit; its locked platform manifest digest is the same content digest published for the Docker Official Image. MinIO's exact Go 1.24.8 compiler is installed from the checksum-verified official Go tarball rather than a floating package repository.
